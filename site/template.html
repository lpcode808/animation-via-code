Animation via code

Short explainer videos made by asking an AI coding agent to write code that draws every frame.

Notes from a few dozen pieces, mostly 15 seconds to 3 minutes: what worked, what broke, and how sure we are of each. Plus prompts, a tiny template and three demos with their source. Not a framework.

01WHY

Why code instead of a video model

A video model grows a clip. Code builds one.

Grown

Fast and beautiful, and hard to correct. Ask for a fix and you get a different clip.

Built

Every shape, number and caption is exact, editable and repeatable. A reviewer says the arrow points the wrong way; you change one line and re-render.

That matters for teaching. If a caption says "3 + 4 = 7", the diagram can be checked against it. The cost is that you, or the agent, have to describe things precisely, and rendering takes minutes, not seconds.

Each frame is a pure function of time. renderAt(t) draws the same picture for the same t, no matter what came before.

That one rule is what lets you render in parallel, re-render one second, and trust that what you previewed is what you ship. The ball above works this way: drag to any point and it's drawn fresh.

  1. PromptTopic, audience, style, length.
  2. Scene codeThe agent writes renderAt(t).
  3. FramesA headless browser captures each one, 30 or 60 fps.
  4. Soundnumpy writes music and effects as raw samples.
  5. MP4ffmpeg joins frames and audio.
  6. ReviewContact sheets, a fresh reviewer, fix, re-render.

That's the most common route, not the only one. Pieces here also used SVG rasterizers, skia-python with no browser (how the demos were made), Manim, Remotion and headless Blender. Pick for the subject.

02DEMOS

Three demos, with their source

Each scene checks itself before it renders.

Drawn frame by frame in Python with skia-python. Each file is one scene: a duration, a draw(canvas, t) that's a pure function of time, a checks() that must pass before anything renders, and a soundtrack written as numpy samples.

Bouncing ball

8 s
What it shows
Physics computed from t, and sound placed from the same physics.
What its check proves
The first landing falls inside the "speeds up" caption, so words and picture agree.

bouncing_ball.pycontact sheet

Pythagorean proof

30 s
What it shows
Four triangles rearranged inside one square, with a live area readout.
What its check proves
The uncovered area, sampled from the triangles as drawn, is c² before and exactly a² + b² after. No triangle turns or flips.

pythagorean_proof.pycontact sheet

Water cycle

20 s loop
What it shows
Evaporation, condensation, precipitation and collection.
What its check proves
The last frame matches the first, so it loops with no jump.

water_cycle.pycontact sheet

What reviewing them caught

  • Bouncing ball. The caption covered the ball once it came to rest, and "It speeds up as it falls" appeared after the first bounce. The floor moved up, the beats were retimed to the physics, and a check now pins them together.
  • Pythagorean proof. The first draft placed two triangles wrong. The geometry checks failed before any frame rendered.
  • Water cycle. Three fade windows didn't wrap round the loop's end, so the seam check failed until they did. The first caption was also too wide, and rain fell through the mountain.
03START

Start here

Five steps, in the order they pay off.

  1. 1

    Try it with a prompt

    Paste the prompt card into a coding agent that can run a browser and ffmpeg, with your topic filled in. Expect 10 to 20 minutes for a 20 to 30 second clip.

  2. 2

    Watch and read the demos

    Three short videos with their full source, each with a check that runs before any frame renders.

  3. 3

    Run the template

    A 6-second browser version of the bouncing ball in about 200 lines: one HTML scene, a render script, a synth soundtrack and a mux step. Its browser render hasn't been run yet, so expect to fix small things.

  4. 4

    Read the guide before your second video

    Filed by stage, from planning to companion pages. Each stage has its lessons, then the bugs that cost time there.

  5. 5

    Steal a prompt

    Demo prompts, a review pass, a long one-shot film prompt, and a brief for turning a video of yourself talking into a motion-graphics edit.

06RUN

Run it yourself

Two ways to render on your own machine.

The demos (tested)

Python 3 with numpy and skia-python, plus ffmpeg. On Ubuntu, skia needs the EGL library even for CPU rendering.

# install
pip install numpy skia-python
sudo apt-get install -y libegl1 ffmpeg fonts-dejavu-core
# render one
cd demos
python3 build.py bouncing_ball

Frames are cached in work/<name>. Delete that folder after changing a scene's draw(), or the old frames are reused.

The template (browser)

Node 18+, Python 3 with numpy, and ffmpeg. Not yet run end to end in a browser; if a step fails, the demos are the tested version of the same idea.

cd template
npm install
npx playwright install chromium
node render.mjs     # 180 frames
python3 audio.py    # audio.wav
bash mux.sh         # out.mp4
07NOTE

A caution on using these notes

Don't paste the whole guide into an agent's standing instructions.

When that was tried, every new video converged on the same pipeline and look. Give the agent the short prompt, and reach for the lessons when something breaks or you want to push past the default.
